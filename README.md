# Smith & Wollensky — Menu & Bar Guest Guide

Статичний гостьовий довідник, зібраний із фотографій меню: Brunch, Lunch, Dinner
і окрема сторінка напоїв. Для кожної позиції розписано склад і позначено алергени.
Інтерфейс, назви страв і всі інгредієнти перекладено **шістьма мовами**:
українська, English, Español, Italiano, Deutsch, Русский.

Відкривається без сервера — просто `index.html` у браузері. Жодних залежностей
і зовнішніх запитів.

## Сторінки

| Файл | Що всередині |
|---|---|
| `index.html` | головна з переходами на всі розділи |
| `brunch.html` | бранч-позиції, бенедикти, Sunday Roast, стейки, гарніри + бранч-сет-меню |
| `lunch.html` | ланч-карта повністю + сет-меню |
| `dinner.html` | вечірня карта + сет-меню |
| `canapes.html` | канапе для приватних заходів — 14 позицій з офіційними алергенами |
| `desserts.html` | десертна карта: десерти, десертні коктейлі, десертні вина, портвейни, херес, чай і кава |
| `drinks.html` | коктейлі, мартіні/мангеттени, Bloody Marys, bottomless brunch, безалкогольні, вина за келихом + digestifs: коньяк, бренді, лікери, ром, віскі |
| `allergens.html` | довідка по 14 алергенах + матриця «усі позиції × алергени» + практичні застереження |

## Навігація розділами

Довгі сторінки не треба гортати: під пошуком є рядок розділів, який гортається
вбік. Натиснув «Основні страви» — видно тільки їх; «Усе» повертає повний список.
Пошук автоматично скидає на «Усе», щоб результати не ховались за активною
вкладкою. На сторінці напоїв так само перемикаються коньяк, ром, віскі та вина.

## Режим застосунку

У корені лежить `manifest.json` з іконками, тож сайт можна додати на домашній
екран і він відкриється без адресного рядка — на Android через маніфест, на iOS
через `apple-mobile-web-app-capable`.

Зум розведено на дві різні речі (`assets/pwa.js`):

* **Подвійний тап** вимкнено **скрізь** — одним рядком CSS `touch-action:
  manipulation` на `html`. Він прибирає саме зум по подвійному тапу, а прокрутку
  й пінч лишає, тож у звичайному браузері нічого не втрачається.
* **Пінч-зум** блокується **тільки в режимі застосунку**: скрипт бачить
  `display-mode: standalone` і переписує viewport на `maximum-scale=1,
  user-scalable=no`, а для Safari додатково гасить події `gesturestart`.
  У браузері пінч лишається навмисно — комусь це єдиний спосіб прочитати склад.

У режимі застосунку кнопки й вкладки також не виділяються від довгого тиску
й не блимають підсвіткою тапу.

Чого тут свідомо немає: перехоплення `touchend` для «подвійного тапу». Воно
гасить не лише зум, а й другий тап поспіль по сусідній кнопці — перевірено, це
ламало перемикання розділів. `touch-action` робить те саме без побічних ефектів.

## Розклад подачі

Позиції, розділи й сторінки можна показувати лише в певні години — без сервера,
на самому клієнті (`assets/schedule.js`).

```js
const SCHEDULES = {
  'set-main':   [{ days: [1,0], from: '12:00', to: '22:00' },
                 { days: [2,3,4,5,6], from: '12:00', to: '17:30' }],
  'late-bar':   [{ days: [4,5,6], from: '22:00', to: '01:00' }]   // через північ теж можна
};

const SCHEDULE_OF = {
  setmenu: { lunch: { key: 'set-main', mode: 'dim' } },
  page:    { brunch: { key: 'set-brunch', mode: 'dim' } },
  section: { brunch: { key: 'set-brunch', mode: 'hide' } },
  dish:    { 'sunday-roast': { key: 'set-brunch', mode: 'dim' } }
};
```

* `mode: 'dim'` — позиція лишається на місці, приглушена, з підписом
  «Зараз не подається. Подається Вт–Сб 12:00–17:30». Для гостя зрозуміліше:
  видно, що страва існує, і коли по неї прийти.
* `mode: 'hide'` — зникає повністю.

Час беремо в часовому поясі ресторану (`Europe/London`) через `Intl`, а не
з годинника пристрою, тому перехід на літній час і гості з іншим часовим
поясом нічого не ламають. Сторінка перевіряє розклад раз на 30 секунд, тож на
межі години перемикається сама, без перезавантаження.

Перевірити, не чекаючи потрібної години: `?at=2026-08-05T19:00` — угорі
з’явиться зелена смужка «Режим перегляду часу».

**Чого це не робить.** Це вітрина, а не захист: гість може перевести годинник,
відкрити код сторінки або зайти прямим посиланням і побачити приховане. Для
меню цього досить. Якщо щось треба закрити насправді — потрібен сервер.

Зараз розклад увімкнено лише там, де години надруковані на самому меню: обидва
сет-меню. Решту налаштовують у панелі.

## Адмін-панель

`admin.html` — сторінка для персоналу. Чотири вкладки:

* **Позиції** — усі 200 страв і напоїв. Для кожної три стани:
  «За розкладом» · «Завжди» · «Немає». Останнє — це класичний 86: страва
  лишається в меню з підписом «Наразі немає».
* **Розділи** та **Сторінки** — те саме, але для цілого розділу чи меню.
* **Розклади** — редактор годин: дні тижня кнопками, час полями, кілька
  діапазонів на розклад, створення нових.

Кожен рядок одразу показує, доступна позиція просто зараз чи ні, а в шапці
йде годинник у поясі ресторану.

Панель розрахована на телефон: керування нагорі й липне при прокрутці,
пояснення згорнуті, кнопки станів на всю ширину рядка.

Інтерфейс панелі перекладено тими самими шістьма мовами, що й меню, з таким
самим перемикачем у шапці — включно з назвами позицій, розділів, днів тижня
й описами розкладів («Пн, Нд 12:00–22:00» / «Mo, So 12:00–22:00»).

### Як зміни доходять до гостей

Панель **не пише на сервер** — його немає. Зміни зберігаються в `localStorage`
браузера, де їх зробили: там сайт одразу показує результат і вгорі висить
зелена смужка «діє незбережена чернетка». Для всіх інших нічого не змінюється.

Щоб оновити для гостей:

1. **Експортувати overrides.js** (або «Скопіювати вміст»).
2. Покласти файл замість `assets/overrides.js`.
3. Запушити — GitHub Pages оновиться за хвилину.

«Скинути чернетку» повертає локальний стан до того, що лежить у репозиторії.

**З телефона** зручніше через «Скопіювати вміст»: скопіювати → відкрити
`assets/overrides.js` на github.com у тому ж браузері → олівець → вставити →
Commit. Виходить, не встаючи з місця.

### Перехід на сервер

Проєкт спроєктований так, щоб бекенд додавався без переписування. Уся
гостьова частина — меню, склад, алергени, переклади — це статичні файли, і
вони не змінюються взагалі. Динамічний тут лише один об'єкт: що зараз відкрито
й закрито.

Щоб увімкнути сервер, достатньо вписати базу в `assets/schedule.js`:

```js
const API_BASE = 'https://menu.example.com/api';   // було ''
```

Далі все відбувається саме собою:

* сторінки гостя забирають стан із сервера при завантаженні й перепитують
  раз на хвилину — зміна доходить без перезавантаження й без пушу;
* кнопка в панелі перетворюється на **«Опублікувати на сервері»** і робить
  `PUT` замість завантаження файлу;
* якщо сервер недоступний, сайт мовчки лишається на `overrides.js` — гість
  бачить останній опублікований стан, а не порожню сторінку.

Контракт мінімальний — два методи одного ресурсу:

```
GET  {API_BASE}/overrides  → 200 { updated, schedules, rules }
PUT  {API_BASE}/overrides  → 204, тіло те саме, лише для авторизованих
```

Формат тіла — той самий об'єкт, що панель експортує зараз, тож наявний
`overrides.js` стає першим станом у базі без конвертації.

Робочий приклад — приблизно тридцять рядків на Node без залежностей:

```js
const http = require('http'), fs = require('fs');
const STORE = './overrides.json';

http.createServer((req, res) => {
  if (req.url !== '/api/overrides') return res.writeHead(404).end();

  if (req.method === 'GET') {
    res.writeHead(200, { 'Content-Type': 'application/json', 'Cache-Control': 'no-store' });
    return res.end(fs.readFileSync(STORE, 'utf8'));
  }
  if (req.method === 'PUT') {
    if (req.headers.cookie !== 'admin=' + process.env.ADMIN_TOKEN) return res.writeHead(401).end();
    let body = '';
    req.on('data', c => (body += c));
    return req.on('end', () => { fs.writeFileSync(STORE, body); res.writeHead(204).end(); });
  }
  res.writeHead(405).end();
}).listen(3000);
```

Замість файлу можна взяти будь-яке сховище — сенс не зміниться. Так само це
лягає на serverless-функцію або на Cloudflare Worker з KV.

Що дає сервер, крім зручності: справжній логін замість «сторінка без
посилань», спільний стан між пристроями (закрив на планшеті — видно в залі
одразу), історія змін і, за потреби, лічильники залишків замість
бінарного «є / немає».

Перевірено наскрізно на макеті бекенда: адмін публікує → гість в іншому
браузері бачить «Currently unavailable» без жодного коміту → повернення
позиції доходить так само → `PUT` без авторизації віддає 401.

### Захист

Сторінка нічим не захищена: вона просто не має посилань з меню й закрита
`noindex`. Хто знає адресу — зайде і зможе експортувати файл, але не змінити
сайт для інших: для цього все одно потрібен доступ до репозиторію. Справжній
логін без сервера зробити неможливо.

## Джерела алергенів

Дані про алергени тепер із двох джерел, і кожна картка це прямо показує:

* **Офіційний лист ресторану** — зелений бейдж із датою перевірки. Дані перенесені
  з Alert65 «Allergens Summary», наданих закладом:
  Mains (14-03-2026), Sauces and dressings (15-12-2025), Sunday Roast (29-12-2025),
  Canapés (12-05-2025), Dessert Cocktails (03-11-2023).
* **Реконструкція з опису в меню** — сірий пунктирний бейдж. Для позицій, яких у
  листах немає.

Офіційні листи розрізняють три стани, і всі три перенесено:

| Позначка | Значення |
|---|---|
| суцільна червона мітка | містить |
| пунктирна сіра мітка | може містити |
| зелений кружечок **R** на мітці | інгредієнт можна прибрати зі страви |

Де лист називає конкретний злак чи горіх, це видно в дужках: «Злаки з глютеном
(ячмінь)», «Горіхи (мигдаль)».

Там, де офіційного листа на страву немає, але є лист на її соус, реконструкцію
підтягнуто до офіційних даних компонента — наприклад, соус «Цезар» офіційно
містить ячмінний глютен і сульфіти, тож усі страви з ним це показують.

## Теми

Перемикач у шапці: **Авто · Світла · Темна**. «Авто» слідує за системною
налаштовкою, явний вибір її перекриває. Вибір зберігається в `localStorage`.
Основний акцент — зелений (активні пункти, кнопки, мітка R, заголовки розділів);
золото лишилося тільки на цінах і декоративній лінійці, щоб його не було забагато.

## Мови

Перемикач у шапці (UA · EN · ES · IT · DE · RU). Вибір зберігається в
`localStorage`; можна також відкрити сторінку одразу потрібною мовою через
`?lang=es`. Якщо нічого не збережено — береться мова браузера, інакше англійська.

Назви страв **не перекладаються** — гість замовляє саме так, як надруковано в
меню. Під назвою йде пояснення обраною мовою, далі — оригінальний опис із меню
курсивом, а нижче повний склад мовою гостя.

### Модель даних

Склад страви — це не текст, а посилання на словник, тому переклади всюди
однакові:

```js
ing: [['bread', ['wheat-flour', 'water', 'yeast', 'salt']], 'butter']
// uk → «Хліб: пшеничне борошно, вода, дріжджі, сіль» · «Вершкове масло»
// de → «Brot: Weizenmehl, Wasser, Hefe, Salz» · «Butter»
```

Марки в барі пишуться дослівно через префікс `~` і отримують категорію в дужках:
`['~Absolut Citron', ['vodka']]` → «Absolut Citron (горілка)» / «Absolut Citron (vodka)».

Алергени в кожної позиції розділені на два рівні:

* `a[]` — **містить**: алерген заявлений в описі меню або однозначно випливає
  зі складу. У картці — суцільна червона мітка, у матриці — `●`.
* `m[]` — **може містити**: типова рецептура закладу, спільний фритюр чи гриль,
  варіативні компоненти. Пунктирна сіра мітка, у матриці — `○`.
* `r[]` — **можна прибрати**: підмножина `a[]`, взята з колонки Removable
  офіційного листа. Мітка R, у матриці — `●ᴿ`.
* `src` — ключ офіційного листа з `SOURCES`; якщо його немає, позиція
  реконструйована.

`w[]` — ключі застережень з `i18n.js` (сира подача, спільний фритюр тощо).

## Фільтр за алергенами

На кожній сторінці меню та в таблиці: гість позначає алергени, яких уникає, і
позиції з ними (або з міткою «може містити») приглушуються. Пошук працює за
назвою страви й за окремим складником — причому **будь-якою з шести мов**,
тому «кунжут», «sesame» і «Sesam» знайдуть одні й ті самі страви.

## Обмеження

Це **неофіційна реконструкція**, зроблена за описами в меню та стандартними
рецептурами, а не офіційна декларація алергенів ресторану. Текст на сайті прямо
просить гостя повідомити офіціанта про алергію перед замовленням.

Відомі прогалини:

* Міцний алкоголь: дегустаційні описи подано так, як надруковано в меню —
  англійською. Зернові дистиляти позначені як «може містити глютен»: після
  дистиляції він зазвичай не виявляється, але для целіакії це варто уточнити.
  Ці позиції офіційним листом не покриті.

* Офіційний лист Mains датований пізніше за сфотографоване меню й описує кілька
  інших страв (Lamb rump, Pan fried Salmon, Pork Chop). Сайт показує сфотографоване
  меню, тож ці три позиції в нього не додано, а `Roasted Lamb Rack` лишився
  реконструйованим — це не той самий відруб, що `Lamb rump` у листі.

* **Red Wine Braised Beef** на бранч-карті — ціну на фото меню не видно; у картці
  стоїть «ціну уточніть у офіціанта». Страва є в сет-меню всіх трьох карт.
* Ланч і вечеря відрізняються лише двома позиціями: `Chicken Fillet Burger` і
  `Signature Steak Sandwich` є на ланчі та бранчі, але не на вечері.
